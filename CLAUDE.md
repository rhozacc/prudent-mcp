# Claude Code: prudent-mcp v0.10

This file is the working brief when extending the codebase. For human onboarding read `README.md` and `docs/corpus/index.md` first.

## What this is

An MCP server that exposes a structured knowledge base for IRB credit-risk model validation. Five parallel surfaces — `regulation`, `tests`, `checks`, `playbooks`, `sources` — each with its own URI scheme, plus cross-cutting tools, a review-area taxonomy, and prompt scaffolds. The `sources` surface is the regulatory-context registry: which documents the corpus derives from and whether that context is current.

The server is the **read-only knowledge layer**. No execution, no writes, no orchestration. That boundary is load-bearing.

Every tool, resource, and prompt has a description, a zod input schema, and a handler. In the open-source distribution the default adapters return empty results. The in-memory demo reassigns adapter handles to seed real content for development and inspection.

## Stack

Bun. TypeScript strict. `@modelcontextprotocol/sdk` (TS-first). zod for runtime validation, template literal types (`type RegulationId = `regulation://${string}``) for compile-time URI segregation.

`bun run typecheck`, `bun test`, `bun run inspect:demo`, `bun run schemas`, `bun run validate`, `bun run graph`, `bun run evals`, `bun run build:mcpb`. `bun run test:ci` runs typecheck + tests + linter + **evals** — the context-quality suite is a gate now, not a report, so a fatal finding fails the build. No `tsc` build step for local dev.

## What to do when extending

1. Read `src/schema.ts` and `docs/corpus/index.md` together — schema decisions all map to a use case.
2. `bun install && bun run typecheck && bun test`.
3. `bun run inspect:demo` — exercise the surface end-to-end.
4. Make your change. Strict mode catches things; trust the type errors.
5. If you change schemas, run `bun run schemas` and commit the regenerated JSON Schemas under `docs/schemas/`.

## Schema decisions worth understanding before extending

- **Template literal URI types** — `Check.derived_from: RegulationId[]` rejects a `TestId` at compile time. Don't widen to `string[]`.
- **`Regulation.children` is mixed but typed** — `RegulationChildId = RegulationId | TestId | CheckId`. A record nests sub-regulations *and* the checks/tests that operationalize it; a `PlaybookId` is rejected at compile time. It stays the denormalized inverse of `parent`, which now also lives on `Check`/`Test`. **Mirror invariant:** a check/test listed as a child must also name that regulation in `derived_from`/`regulatory_basis` (and point back via `parent`), so `get_referrers` remains the single computed reverse index — don't add a second scan over `children`.
- `Check.derived_from` + `Check.expectation` + `Check.expected_evidence` — traceability from supervisor expectations back to law, plus the concrete artifacts a reviewer must gather. Without `derived_from`, a Check is opinion. Without `expected_evidence`, it's underspecified.
- **Check URI shape** — `check://{area}/{topic}[/{specific}]` (e.g. `check://calibration/pd/lra-derived`). Hierarchical, consistent with `regulation://`. Don't flatten back to `check://slug`.
- **`Source` is a currency registry, not referenced content** — `source://{framework}/{document-id}`, latest-only (supersession = `status` + `superseded_by`, linter-enforced: the two imply each other, pointers resolve, chains are acyclic). It stays out of `children`, `get_referrers`, `AnyId`, and the mirror invariant; the join to regulation is `framework` + `document_id` string equality, computed where needed. `verified` drives the 30-day staleness surfaced by `get_corpus_info.stale_sources` and `bun run validate` warnings; `milestones` are chronological display strings (never parsed) and `milestones[0]` is served as `next_milestone`. Maintenance = `/maintain-context` session edits gated by the linter, never write tools. **`Source.coverage` (`'full' | 'partial'`) is OPTIONAL and absent means NOT DECLARED** — never defaulted, because a corpus holds a subset of the articles of most of what it names and a defaulted `'full'` would be a claim nobody made (see the holdings bullet below). **`Source.pending_changes` is optional on the same terms: absent = the registry never looked, `[]` = it looked and found none** (see the pending-change bullet below).
- **Review areas are keyed in ONE place (`src/areas.ts`)** — playbooks carry `area`/`subarea` as free-form prose from extraction ("PD Estimation"); the taxonomy addresses the same nodes by dotted slug. `areaKey`/`resolveArea`/`playbookInArea` are the only definitions of that mapping, and `get_area_overview` accepts either spelling. Two consequences worth keeping: an authored `taxonomy` in the corpus always wins, and when there is none it is **derived from the playbooks present** rather than served as `[]` — an empty taxonomy takes `list_review_areas` AND `get_area_overview` out of service, which is the documented entry path. Don't reimplement the `p.area === area` filter anywhere; that comparison is a slug against prose and can never match.
- **Search ranks by COVERAGE first, then score** — score is a sum over query tokens, so on the real corpus "long run average default rate" matches 707 of 1,365 regulations and "margin of conservatism data quality" matches 984 of 1,107 checks. Summing alone let a record matching only the commonest token outrank one matching every token. `SearchMatch` carries `coverage` and `query_tokens`; a single-token query has coverage 1 everywhere and falls through to score exactly as before. Don't "simplify" the sort back to score.
- **`list()` vs `search()` on every content adapter** — `list()` returns ALL records and is the enumeration/traversal contract (cross-cutting tools, scripts, validators, completions). `search(query)` is ranked, field-scoped relevance search via `src/search.ts` (`rankedSearch`, per-surface field sets, **no cap** — the tool layer pages); an empty/whitespace query returns `[]`. Never lean on `search("")` to enumerate — that undocumented contract is gone, and the tool layer rejects sub-2-char queries anyway. The one-call corpus dump mattered: the corpus is the paid product.
- **Ranking returns everything; the TOOL layer pages** — `rankedSearch` used to slice to 20 before `paginate` counted, so `total_matches` reported a page size on every query of every surface, and paging past it returned nothing — which made the obvious way to verify the number confirm it. `DEFAULT_LIMIT` is `Infinity`; `total_matches` is `all.length`. Don't reintroduce a cap inside ranking.
- **Query tokens are stopword-filtered; excerpts are whole sentences** — `"of"` substring-matches inside "proof", which handed every record a free point of `coverage` (the primary sort key) and pinned the excerpt window to the head of the record. Filtering is by list, never by length: a legal point segment (`180(1)(a)`) is one character and carries meaning. `makeExcerpt` then returns a run of WHOLE sentences around the densest hit cluster — an excerpt cut mid-clause cannot be quoted, so the caller opens the full record anyway and the excerpt has cost tokens for nothing. A legal act numbers its obligations `(a) …; (b) …;` with no terminator until the end, so `sentenceSpans` sees one span for the whole article: 992 of 5,629 spans exceed the window and hold 44.3% of all regulation text. For those the window falls back to the nearest CLAUSE end (`. ! ? ;`, never `:`) — fixing it in `sentenceSpans` instead orphans enumerated limbs from their stem (3.3% → 15.4%), which is worse than a long excerpt. The head never snaps forward onto a limb: an excerpt starting at "(b)" has lost the sentence that says what (b) is a list of.
- **Search rows say how much of the query they matched; the envelope says whether anything did** — a page of hits on the commonest query terms reads as an answer, so on a topic the corpus lacks the server handed back 100 plausible rows and no signal. Concise rows on all four search tools carry `coverage`; the envelope carries `query_tokens` (distinct terms via `distinctQueryTokens`) and `best_coverage` (best over the WHOLE ranked set, so page 2 reports what page 1 did; absent when nothing matched). A `notice` fires when `best_coverage * 2 < query_tokens` and is APPENDED to any truncation or shortening notice, never replacing it. It is a statement about the corpus, not the law. No relevance floor, no cap, order and `total_matches` untouched. ONE helper, `rankedSearchResult` in `tools/shared.ts`, serves all four tools — don't copy it per tool and don't reintroduce a per-tool recompute. The adapter interface still returns records only: coverage is recomputed in the tool layer from the returned records with the adapter's field set, so an outside adapter needs no new method. The rule is deliberately a fixed fraction: a query dominated by digit fragments (72.5 splits into 72 and 5) can show high coverage on a topic the corpus lacks, because short digit tokens match almost everywhere — a tokenization property, not a notice bug.
- **One response, one size ceiling** — `serialize` (compact, not indented) is the single encoder for every tool body AND the thing every budget measures, so a page shortened to fit cannot arrive larger. `paginate` shrinks the page until the rows fit `RESPONSE_CHAR_BUDGET` (never to zero: an empty page reads as "no matches"), and `fitOrCompact` serves a bundle's compact form when its full form does not fit. Both say so in `notice`. Nothing is ever dropped silently — `search_regulation(detail:'full')` caps `commentary` and declares `commentary_omitted`, because a handful of section records carry 40-56 entries and one of them serialized to 33,000 characters.
- **`resolve_citation` declines** — `resolveCitationDetailed` returns `CitationResolution` (`match`, `confidence`, `candidates`, `ambiguous`, `unmatched_segments`, `coverage_note`), never a bare `Regulation | null`. Matching is exact, in order: exact citation equality, then equality against a record's declared aliases (first, so no gate can refuse a record the caller quoted) → instrument gate (a citation naming an instrument the corpus does not hold resolves to null with a note, never into another document that shares a number) → exact numeric-SPINE equality scoped to the document the citation names → narrower relatives reported as candidates with `match` still null → the MIRROR of that, the containing provision, reported the same way. Containment and suffix matching as *matching* are gone: they made "Article 1218" resolve to 121 and "Article 178 of the CRR" land on whatever document had a 178, with no way to tell a hit from a guess. The container mirror is not that returning — `match` stays null and `confidence` stays `"none"`; it only stops the corpus saying "nothing is numbered 181.1.b" about a point it serves verbatim inside Article 181 (377 → 124 bare misses over the 456 targets the corpus asserts about itself, 0 match flips). Two guards make it safe and both are load-bearing: a record whose citation reduces to an empty or non-faithful spine is a prefix of everything (`Section P3.TIV.C1b.S2b-3` reduces to `["3"]`), and spine tokens are compared JOINED ON A SEPARATOR — `"article41"` was once both `Article 4(1)` and `Article 41`. **A confident wrong citation is the worst failure this server can produce.** Don't add a fuzzy fallback, and don't fold candidates into `match`.
- **`resolve_citation`'s instrument gate has two parts, and a note may only claim what it verified** — (0) is by NUMBER: `crr`/`crd`, each one instrument however it is named (short name, English name, official number in either order), and numbered acts in every standard spelling (`Directive 2014/65/EU`, `Regulation EU 2019/2033`, a bare `Decision 2021/451`, `Guideline (EU) YYYY/NNN`) and with the number first (`2019/2033 Regulation`; the CRR's number beside another kind's word, `575/2013 Directive`, is that other act, which is not held, and never the CRR); the refusal quotes the institution the caller wrote and the era's form of the number, and a year is a year only from 1958 on (`1907/2006` is serial/YEAR). (0c) is a document named by NUMBER (`EBA/GL/2018/04`: authority, optional kind, year, serial) that no held document answers to: declined, because its year and serial would otherwise read as points of a provision. (0b) is by DESCRIPTION, from ONE table (`DESCRIBED_INSTRUMENTS` in `src/file-adapter.ts`), in every spelling of a kind: RTS in any case, plural or dotted (`rts`, `RTSs`, `R.T.S.`); ITS in upper case, plural or dotted, and in any case straight after a determiner (`its` is a pronoun everywhere else); regulatory/implementing technical standards and a bare technical standards (either kind releases it); delegated/implementing regulation|decision|act; ECB (or European Central Bank) regulation|guideline|decision|recommendation; guideline of the ECB; words separated by any run of white space or dashes. A gate that reads one spelling is walked round by the next, so I3's probes carry the respellings. "The RTS on …" used to fall through to a provision elsewhere that shared the article number. The descriptive gate returns `match` null, `candidates` `[]`, `confidence` `"none"` when no held document identifies as that kind; held-ness is whole-token matching on framework, `document_id` and id segment, never substrings; it fires only when a provision number is present; a descriptor followed by an act number belongs to the number gate; naming a held document AND an unheld described instrument declines naming both, except an ECB-kind descriptor (the table's `issuer`) beside a held document of that framework, which is one document called twice and resolves as if the descriptor were absent (never when it carries a number or identifier, names another issuer's document, or sits beside a held instrument). With no document named the decline lists the held documents under the issuer's framework in the note only: `candidates` stays `[]`, and a note quotes the descriptor's own words, stopping at a held document's name. Don't add curated facts about particular real instruments for descriptive names — the note states no requirements. The numbered-act pattern is defined once (`NUMBERED_ACT` / `numberedActKeys`) and the gate and the mention scan share it. Rule (iv), the containing provision, verifies before claiming, and only for ONE document: when the containers sit in several documents there is no "the container" (they are different provisions that share a number) and the note lists the narrowest of each and gives no verdict on any text. `textCarriesPoint(text, segments)` in `src/file-adapter.ts` is the ONE reader and returns `yes | no | unknown`. Only a verified `yes` may say the text "carries" the point; `no` says it was not found and the numbering may differ; `unknown` says it could not be established. Conservative by construction (runs not bags: "9." counts only after 1..8; scoping per segment; a `no` only when the text demonstrably numbers items that way). `match`/`confidence`/`candidates`/`unmatched_segments` and both guards (faithful spine, non-empty spine) are unchanged.
- **A name the registry or the instrument supplies scopes a citation only when it is accounted for** — `documentAliases` indexes the ids the records carry (framework, document id, id segment: exact, they scope a citation whatever else it says) and, from `holdings`, registry titles; `withInstrumentNames` adds the instruments the citation mentions (English name, official number in either order, a bare number only with no other kind's word in front of it). The last two are DERIVED: they win over an id by being longer, so they are accepted only when nothing else in the citation could name another document (`accountedFor`: structure, filler, a name for the same documents or their framework, no second instrument still named) or the rest is exactly a record's own citation; otherwise the ids alone decide, exactly as before they existed. That guard is load-bearing: without it "Paragraph 181 of EBA guidelines on X referred to in Regulation (EU) No 575/2013" is read out of the regulation the guidelines are merely issued under. (0d) declines, with no candidates, content words after the last of/in/under/from when no document is named. Two things stay out: a derived name never joins the id set, and the fallback never picks a document by the longest name. `CONNECTIVES` (never a single letter: point (a) is a point) are set aside only in the `coreHits` pass, which breaks a spine tie in favour of the record whose own citation says what was asked and keeps the label `segment`.
- **`Source.coverage` and `CorpusInfo.holdings` — the coverage list names documents, not how much of each** — `get_corpus_info.coverage` read `["CRR", …]` as though a name were the whole instrument, so a miss on a provision of a partly held document read as "the provision does not exist". `src/holdings.ts` is the ONE definition: `CorpusInfo.holdings` (`{ document_id, framework, title, records, partial? }`) is optional and computed at serve time even when a stored `corpus_info` ships; `partial` is true/false only when a CURRENT source declares it (key absent otherwise — absent is not full); only current sources speak for a document, and where they conflict partial wins. The `coverage` list is untouched. All regulation id misses go through `unknownRegulationMiss`; don't reintroduce a bare "No record for" sentence on any regulation tool. `resolveCitationDetailed(regulations, text, holdings?)` takes holdings as an optional third parameter: the partial clause explains an ABSENCE only — `match` stays null and `confidence` stays `"none"`, and the container note deliberately carries no clause. `DocumentHolding` is embedded in `CorpusInfo` and not in `scripts/schema-registry.ts`, so the schema count is unchanged.
- **Pre-adoption placeholders are flagged from the served text, on two tools** — a guideline written before a technical standard was adopted names it as "Regulation (EU) xx/xx"; a model resolved that to a numbered act from memory, or read it as a citation. `pre_adoption_placeholders` + `notice` are computed additive keys on `get_regulation` and `expand_regulation` ONLY (`src/placeholders.ts`), declared optional at `get_regulation`'s declaration site; the canonical `RegulationSchema` and `docs/schemas` are untouched. They are absent, not empty, on every other record. The scan needs an instrument word plus an act number with a stand-in half, so numbered acts, bare `xx` and quotation elisions never trigger it: a false flag calls a real citation not-a-citation. `detail: 'full'` search rows and `resolve_citation`'s `match` are deliberately undecorated.
- **`Source.pending_changes` and `pending_changes_note` — the registry says what the snapshot is behind on, document-level, computed at serve time** — `PendingChange { title, reference?, status: announced | adopted, effective_from? (ISO, PARSED), ingested: boolean, affects?: string[] (free text for a reader, NEVER parsed or matched), note?, url? }` on a source. `src/pending.ts` is the ONE definition: `pendingState` is `ingested` | `upcoming` (`effective_from` after today) | `in_force_not_ingested` (today or earlier: the served text may no longer be the text in force) | `undated`, derived from the stored `ingested` + `effective_from` and a `today` that is a PARAMETER, never stored (a stored state is wrong the morning after the day). **Absent is not empty**: a source without the key says nothing, `[]` says looked-and-none (`verified` says when); `CorpusInfo.pending_changes` is served only when some source declares the key. **Only a CURRENT source speaks** (as `computeHoldings` does for coverage). The join is `framework` + `document_id` and is DOCUMENT-level: the note rides on every record of the document and `affects` is only quoted back as a hint ("Registry: concerns …"), because the server cannot know which provisions an amendment touches and the corpus does not hold the amendment. `pending_changes_note` (a leading additive key, after `as_of_note` when both apply) is on `get_regulation`, `expand_regulation`, `get_regulation_tree` (the ROOT's document, once) and a `resolve_citation` `match` (never on a decline); `search_regulation` appends one sentence to `notice` for documents on the page, computed from the rows actually on the page (`pageNotice` in `rankedSearchResult`, after the truncation/weak-match notices); `get_corpus_info.pending_changes`, `list_sources.open_pending_changes` (absent at zero) and `get_source` per-change `state` carry the rest. Under `as_of` a change whose `effective_from` is AFTER the date is left out (the text of an earlier date is not behind it); an undated change stays. The note names at most 3 changes (in force first, then soonest, then undated), says what the state means and nothing about what the change provides, and is ABSENT when nothing is open — never a reassurance, because "no pending change recorded" is not "none is coming". The tool layer reads `adapters.source.list()`, so an outside adapter needs no new method. `bun run validate` warns on a change that is in force and not ingested and prints an info count. The canonical `RegulationSchema` and `docs/schemas` are untouched for the note (declared optional at `get_regulation`'s declaration site); `PendingChange` is embedded in `Source`, not a registered schema.
- **Optional record fields are OPTIONAL, not defaulted — absent is not empty** — `Regulation.citation_aliases/kind/obligation/pages/anchor/is_metadata_only/cites` and `Check/Test.primary_basis` are all `.optional()`. `pages: []` asserts the text was read from no page; `pages` missing says the corpus never captured it. Defaulting them would erase that distinction, which is the same defect as `next_milestone` reading "nothing upcoming" for a registry where milestones were never populated. A corpus that omits them all behaves exactly as before.
- **`citation_aliases` resolve, at their own confidence level** — an alias hit returns `confidence: "alias"` plus a note naming the record's real citation, never `"exact"`. The caller asked for a label the record does not carry: EBA guidelines number paragraphs, and "Article 178" is simultaneously a real CRR article. Fold `"alias"` into `"exact"` and the collision the relabel fixed comes straight back.
- **`get_referrers.primary` is the discriminating half** — `derived_from` is a span (a median of 23 ids, because a check read off a section is traced to the whole section), so the flat lists return the same answer for every article in that section. `primary_basis` names what a check restates; `computeReferrers` splits it out and the tool tells the caller to prefer it. Empty on a corpus that carries none, which is distinguishable from "nothing restates this".
- **Published output schemas are OPEN** — every tool that declares an `outputSchema` declares it with `.passthrough()`, at the declaration site only (the canonical record schemas in `src/schema.ts` stay closed, and the registered JSON Schemas under `docs/schemas/` are byte-identical). A closed envelope publishes `additionalProperties: false`, so a spec-following client REJECTS a response carrying a key the schema does not name — which turns every additive field into a breaking change for exactly the careful clients. `miss()` is contract-free because the SDK returns before validation when `isError` is true. Don't "tighten" these back. `get_regulation` publishes `RegulationSchema.extend({ as_of_note, pre_adoption_placeholders, notice: optional }).passthrough()` at the declaration site, so the schema a client reads names the caveats a hit can carry; the canonical `RegulationSchema` and `docs/schemas` stay byte-identical.
- **The instructions block carries RULES about the EDGE of the corpus, not facts about one** — scope (a bounded corpus; absence from it is not absence from the law; `get_coverage_gaps` measures coverage of provisions by checks INSIDE the corpus, never coverage of the law by the corpus), answering past the boundary (neither truncate at it nor blend across it — label what is not traceable to a record id, and a pre-adoption `xx/xx` placeholder is flagged on the record and is not a citation), holdings (on a partly held document a miss or a null `resolve_citation` match is absent from the corpus, not nonexistent), search coverage (read `best_coverage` before treating the top of a list as an answer), `as_of_note` (current text served under `as_of` is not evidence of what applied on that date), `pending_changes_note` (a change the registry records and the corpus has not ingested: the served text is the version before it and may already be out of date — say so, with the date), and legal force vs drafting register (`obligation` is how one provision is WORDED and `doc_type` is a format label; neither carries tier — resolve force from the empowering provision's served text). They are there because a grounded answer once lost to an ungrounded one on precisely this: the server was authoritative about what it held and silent about everything else, so the model took the corpus boundary for the boundary of the subject. They are counted in `surfaceTokens` (instructions ~1,294 tok of a 6,149 surface against a 6,200 ratchet, so any new rule must be paid for by tightening a tool card — the four search cards' coverage sentence went into the instructions once for exactly that reason), and they are rules rather than facts because this repo is public and corpus-agnostic.
- **The evals are truthfulness gates, and each says `applicable: false` rather than pass on nothing** — I1-I4, I7 and I11-I15 are the truthfulness groups and fatal; I6 (cost) warns; I8 measures findability. I11 (as_of is never silently substituted) and I12 (a decline on a partly held document says so; n/a when no document declares partial) read the corpus file for facts only where the reply cannot tell them — an eval that infers a corpus fact from reply equality alone raised a false fatal on a correctly versioned corpus. I3 includes `I3/descriptive-instrument` (held kinds read from `get_corpus_info`, not from the reply) and `I3/container-claim` (every note saying the containing record carries a point is checked against the served text; n/a when no probe reaches rule iv). I13 (a weak best match is declared) and I14 (placeholders are marked) bind the search envelope and the placeholder flag; I15 (a pending change is never silent) reads the registry through `get_source`, checks each served `state` against the date arithmetic its own fields imply, and requires the note on every tool that serves a record of a document with a change not ingested — and none on a document with nothing open or under an `as_of` before the change (n/a when no current source has an open change; the seeded demo's CRR source carries one); I16 checks replies against the published output schemas. `bun run test:ci` runs them; the seeded demo's CRR source declares partial so I12 binds there.
- **Ids must survive being written down (linter rule 7)** — `[^A-Za-z0-9:/._-]` in any id is fatal. An id is copied out of one response into the next call, usually inside prose, and every URI extractor stops at a bracket: an id ending in `(part2)` reached `get_check` as `…/2(part2`, which reads as "no such record".
- **`regulation_history` + the `as_of` rule** — the corpus file's optional `regulation_history` key (`{ id, effective_from, record }` entries) powers `get(id, asOf)`: no history for the id → current record, UNLESS the registry says the document did not exist yet (the earliest `published`/`effective_from` across that document's sources) — a 2016 `as_of` against a 2019 guideline is a miss, not today's text relabelled, and that needs no history at all; history present → last entry with `effective_from <= asOf`; asOf predating every entry → `null`, never current text served as historical. The current version is asOf-selectable only via a current-boundary entry. **`RegulationAdapter.resolveAsOf?` is an OPTIONAL method** returning `{ record, basis: 'history' | 'current' }` or `{ record: null }`; it is the single selection logic and `get(id, asOf)` delegates to it. `basis: 'current'` means the current record stood in for a version the corpus does not record: `get_regulation` / `expand_regulation` then carry an additive `as_of_note`, and `get_regulation_tree` carries one on the ROOT envelope counting the other current-text nodes. The first version of this served current text under `as_of` with nothing to say so — a hit that read as the text of the date. Hits that are still served stay hits and misses are unchanged; the note names `document_version` and says not to present the text as historical. It is absent (never empty) without `as_of`, with history covering the date, and on a miss. An adapter without the method is served through `get(id, asOf)` with no substitution note, because unknown is not history. `expand_regulation` resolves its regulation children under the same `as_of` (up to 0.8 it embedded their latest text whatever the date), and a child or tree node the corpus LISTS but has no version of for the date comes back as a bare id, which on its own reads as a dangling reference: `resolveRegulation` reports it as `noVersion` and the group note counts it apart from the nodes served from current text (an id the corpus does not hold at all is not counted). Don't fold current-basis into a miss and don't stamp tree nodes individually. The resolution lives once in `tools/shared.ts` (`resolveRegulation`, `asOfNote`, `asOfGroupNote`, `withAsOfNote`). `RegulationHistoryEntrySchema` is exported but deliberately NOT in `scripts/schema-registry.ts` (it's file-format plumbing, not a surface schema).
- `Test.family` + `Test.aliases` + `Test.acceptance_criteria` — equivalence reasoning across bank-specific test variants.
- `Regulation.commentary` — interpretive material (Q&A, supervisor letters), source-attributed.
- `Playbook.phases` — structured walkthrough with mixed-surface references in each phase.
- `ReviewArea` — canonical taxonomy. The map from "what an analyst is doing" to "what's in the corpus."

## Design constraints

- Read-only. No write tools.
- No execution. The server describes; computation lives elsewhere.
- Versioning only on `Regulation`. Other surfaces always serve latest; source supersession is a `status` + pointer, not history.
- URI schemes match surface names.
- Cross-surface references are typed.
- Strict TS (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`). Keep both on.
- **Licensing is settled — don't drift it.** The server code is AGPL-3.0-only
  (`LICENSE`, `package.json`, `manifest.json`, `README.md` and `docs/index.md` must
  all agree). The corpus is proprietary, licensed separately, and never enters this
  repo. Embedding/OEM/on-prem is offered under a commercial licence instead. The
  copyleft is deliberate: the server ships only a stdio transport, so any hosted
  deployment is a modified work and §13 reaches its transport, auth and metering
  layer — that is the asset being protected, not the corpus, which no code licence
  can reach. Anything bundled into the `.mcpb` needs its notice in
  `THIRD-PARTY-NOTICES.md`.

## Don't add (yet)

- Authentication, rate limiting, telemetry.
- More reference adapters under `examples/`. The in-memory demo is the template; backend-specific adapters belong outside this repo.
- More prompts beyond the existing three scaffolds.
