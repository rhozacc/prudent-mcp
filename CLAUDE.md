# Claude Code: prudent-mcp

Working brief for extending this repo. Humans start at `README.md` and `docs/corpus/index.md`; the 1.0 design is `docs/design/1.0.md`; the history of every rule below is in `CHANGES.md` and in the comments at the code site named next to it. This file holds the rules and the one-line reason for each, not the story.

## What this is

A read-only MCP server over a structured knowledge base for IRB credit-risk model validation. Surfaces: provisions (`regulation`), `tests`, `checks`, compiled per-topic `playbooks`, and the `sources` registry, each with its own URI scheme. The first call a model makes is `brief`, which routes a question to the playbook that answers it. Playbooks are COMPILED by the private factory (prudent-corpus) and only verified and rendered here. The corpus is proprietary and never enters this repo; the demo corpus in `examples/` is the only data here.

**Surface:** 8 tools (`brief` `playbook` `topics` `search` `get` `cite` `related` `sources`), 5 resource templates (one per URI scheme), 1 prompt (`walk_through`). Registration is explicit in `src/server.ts`.

## Layout

```
src/server.ts            instructions (~300 tokens, held by tests/instructions.test.ts) and registration
src/schema.ts            zod schemas + template-literal URI types; PlaybookSchema is the compiled playbook

src/file-adapter.ts      adapters over a corpus JSON file and regulation_history; re-exports the resolver's public names
src/citation/            the citation resolver: tokens, points, names, instruments, described, aliases, resolve (index.ts is `prudent-mcp/citation`)
src/brief.ts             routePlaybooks: BM25F over playbooks + a vote of the provisions a question finds
src/render.ts            a playbook as deterministic text; citations come from ids; budgets
src/playbook-verify.ts   verifyPlaybook V1-V8, the gate between a compiled draft and a reader (pure)
src/playbook-context.ts  the plain maps render and verify read (NOT src/tools/served-context.ts)
src/search.ts            rankedSearch (BM25F) and the per-surface field sets: the ONE ranking definition
src/citation-style.ts    citationOf / locatorOf: the ONE official-citation definition
src/holdings.ts, pending.ts, amendments.ts, placeholders.ts, crossrefs.ts, referrers.ts
                         each the ONE definition of its concept, computed at serve time
src/language.ts          BANNED_TERMS, the language rule
src/tools/               one file per tool, plus shared.ts (paging, size, notes plumbing) and notes.ts
src/validate.ts          the corpus linter behind `bun run validate`
plugin/                  the Claude Code plugin; server/index.mjs is GENERATED by `bun run build:plugin`

```

## Stack and commands

Bun, strict TypeScript (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`: keep both on), `@modelcontextprotocol/sdk`, zod. No `tsc` build step.

- `bun run test:ci` is THE gate (typecheck, tests, linter, evals). CI runs exactly this; run it before every commit.
- `bun run inspect:demo` exercises the surface; `bun run evals:call <tool> '<json>'` drives one tool.
- Changed a schema: `bun run schemas`, commit `docs/schemas/`. Changed `src/`: `bun run build:plugin` and commit the bundle (`tests/plugin.test.ts` fails otherwise). `bun run graph` regenerates `docs/corpus/graph.md`; do not hand-edit it.

## Rules that are load-bearing

**Boundary**
- Read-only: no write tools, no execution, no orchestration. Why: the server is a knowledge layer; a write surface is a different product with a different threat model.
- Playbooks are compiled elsewhere and only rendered and verified here. Why: synthesis at query time under a context budget was the measured failure (`docs/design/1.0.md`).
- Versioning exists only on `Regulation` (`regulation_history`). Everything else serves latest; source supersession is `status` + `superseded_by`.
- Don't add: authentication, rate limiting, telemetry, more reference adapters under `examples/`, more prompts. Why: they belong in hosting layers, not the open server.
- This repo is public. No corpus text, ids or counts from a real corpus in code, tests, comments, notes or issues. No rule or note names a particular real document.

**Schema**
- Template-literal URI types segregate surfaces at compile time (`Check.derived_from: RegulationId[]` rejects a `TestId`). Don't widen them to `string`.
- URI shapes match surface names; `check://{area}/{topic}[/{specific}]` is hierarchical like `regulation://`.
- `Regulation.children` is mixed but typed (`RegulationId | TestId | CheckId`); a check or test listed there must name the regulation in `derived_from` / `regulatory_basis` and point back via `parent`. Why: `related` is the single computed reverse index (`src/referrers.ts`); a second scan over `children` would drift.
- A Check without `derived_from` is opinion; without `expected_evidence` it is underspecified. `primary_basis` names what a check restates, and `related.primary` leads with it because `derived_from` is a span.
- **Absent is not empty.** `Regulation.citation_aliases/kind/obligation/pages/anchor/is_metadata_only/cites`, `Check/Test.primary_basis`, `Source.coverage` and `Source.pending_changes` are `.optional()`, never defaulted. Why: `pages: []` says "read from no page"; a missing key says "never captured". `coverage` absent means NOT DECLARED (a defaulted `'full'` is a claim nobody made); `pending_changes: []` means "looked, found none". Defaulting erases that and produces confident false statements (`src/holdings.ts`, `src/pending.ts`).
- `Source` is a currency registry, not content: latest only, outside `children` / `related` / `AnyId`. The join to a regulation is `framework` + `document_id` string equality. `verified` drives the 30-day staleness warning; `milestones` are display strings, never parsed.
- Ids must survive being written down: any character outside `[A-Za-z0-9:/._-]` is a fatal linter error (`src/validate.ts`). Why: ids are copied into prose, every URI extractor stops at a bracket, and a truncated id reads as "no such record".

**Search and responses**
- Search is BM25F over STEMMED terms, one definition in `src/search.ts` (field weights, IDF, k1 = 1.2, b = 0.75). Coverage is a signal, not a sort key, with one guard: a loose-only match (coverage 0) never outranks a typed-word match. Field sets are module constants because the index is cache-keyed on them. No derivational stemming (measured: it lost ground; the reasoning is on `stem`).
- `list()` enumerates everything; `search()` ranks. Never use `search("")` to enumerate. Why: a one-call corpus dump would hand over the paid product.
- Ranking returns everything; the TOOL layer pages. Don't reintroduce a cap inside ranking. Why: a cap made `total_matches` report a page size and made verifying it confirm the error.
- One response, one size ceiling: `serialize` (compact) is the single encoder AND what every budget measures; `paginate` shrinks to fit `RESPONSE_CHAR_BUDGET` but never to zero; `fitOrCompact` serves the compact form when the full one does not fit. Both say so in `notice`. Nothing is dropped silently.
- Search rows carry `coverage`; the envelope carries `query_tokens` and `best_coverage`, and a weak-match notice fires when `best_coverage * 2 < query_tokens`. ONE helper (`rankedSearchResult`, `tools/shared.ts`) serves every search; don't copy it per tool.
- Query tokens are filtered by a stopword LIST, never by length (a point `(a)` is one character and carries meaning). Excerpts are whole sentences, falling back to the nearest clause end for unterminated enumerations (`makeExcerpt`, `src/search.ts`).
- **Published output schemas are OPEN** (`.passthrough()` at each declaration site, never on the canonical record schemas). Why: the SDK publishes closed schemas as `additionalProperties: false`, so a strict client would REJECT any response with an added field and every additive field would be a breaking change. Don't "tighten" them.

**Notes and language**
- Edge-of-library rules travel as NOTES (`src/tools/notes.ts` is the ONE place): `amendment | version | outside_library | placeholder | weak_match`, written to be repeated to the user, ABSENT (never empty, never a reassurance) when there is nothing to say. Why: a model took the boundary of the library for the boundary of the subject when the server was silent about it. The instructions stay about 300 tokens and say only how to start, how to cite, to repeat each note and to name an instrument the library lacks.
- **The language rule** (`src/language.ts`, eval I17): server-authored text never says what `BANNED_TERMS` lists (corpus, ingest*, registry, record(s), holdings, adapter, served, "this server"); the self-reference is "this library". Why: a model repeats what the server says, so plumbing words turn an answer about regulation into a description of a tool. MODEL-FACING text (instructions, descriptions) may name tools and fields in backticks; ANSWER-BEARING text (every `notice` and note) may contain no identifier at all. A string that trips I17 is rewritten, not exempted. Record text is data and is never scanned.
- Playbook text: V5's word list is the language rule less "record", "holdings" and "served", plus "record id".

**`cite`**
- A confident wrong citation is the worst failure this server can produce. `resolveCitationDetailed` returns `CitationResolution` (`match`, `confidence`, `candidates`, `ambiguous`, `unmatched_segments`, `coverage_note`), never a bare record. Matching is exact and ordered (exact, alias, instrument gate, numeric spine within the named document); narrower relatives and the containing provision are reported as `candidates` with `match` still null. Don't add a fuzzy fallback and don't fold candidates into `match`.
- `"alias"` confidence is distinct from `"exact"`: EBA guidelines number paragraphs, and "Article 178" is also a real CRR article.
- The instrument gates decline a citation naming an instrument the library does not hold, by NUMBER (every standard spelling), by identifier, or by DESCRIPTION (`DESCRIBED_INSTRUMENTS`, one table, every spelling of a kind). A gate that reads one spelling is walked round by the next, so I3's probes carry the respellings. A derived instrument name scopes a citation only when it is accounted for (`accountedFor`); otherwise the ids alone decide. A note may only claim what it verified: `textCarriesPoint` is the ONE reader and returns `yes | no | unknown`. Both guards of the container rule (a faithful, non-empty spine; spine tokens joined on a separator) are load-bearing. Rationale and counts: comments in `src/citation/`, `CHANGES.md`.
- Don't add curated facts about particular real instruments for descriptive names; a note states no requirements.

**Pending changes and `as_of`**
- `pendingState` is derived from `ingested` + `effective_from` and a `today` that is a PARAMETER, never stored. Only a CURRENT source speaks. The note is provision-level (`src/amendments.ts`): a provision is told only when an `amends` entry or an `affects_ids` names it. A document with open changes and neither says so once, at document level. Why: a document-wide note made a model repeat "may be out of date" about paragraphs the change never touched. `affects` is free text and is never parsed.
- `as_of`: history present selects the last entry at or before the date; a date before every entry, or before the document existed per the registry, is a miss, never current text relabelled. When the current record stands in for an unrecorded version the response carries a `version` note (`resolveAsOf`, `tools/shared.ts`). Don't fold current-basis into a miss, and don't stamp tree nodes individually.

**Playbooks and routing**
- A citation in rendered text comes from the provision id through `citationOf`, never from the compiler. The verifier is pure and each rule (V1-V8) is a failure actually seen; add a rule only with a failing fixture. `brief` routes with a floor and a margin tuned on a question bank held outside this repo (`ROUTING_BANK_VERSION`); change them on that evidence and keep I19 passing.

**Evals**
- `evals/` are truthfulness gates, not reports: I1-I4, I7, I11-I15, I17 are fatal, I6 warns, I8 measures findability. Each says `applicable: false` rather than pass on nothing. A suite that measured nothing fails. Never weaken a threshold; an invariant that no longer binds is a finding to report. The `evals --json` shape and the invariant ids are read by the factory repo; don't change them.

**Licensing is settled.** Server code is AGPL-3.0-only (`LICENSE`, `package.json`, `manifest.json`, `README.md`, `docs/index.md` must agree); the corpus is proprietary and licensed separately. Why: the server ships only stdio, so any hosted deployment is a modified work and §13 reaches its transport, auth and metering layer, which is the asset being protected. Anything bundled into the `.mcpb` needs a line in `THIRD-PARTY-NOTICES.md`.

## When extending

Read `src/schema.ts` with `docs/corpus/index.md`, run `bun install && bun run test:ci`, make the change, keep the public export paths in `package.json` working (the factory and the console import them), and add a `CHANGES.md` entry for anything a user of the server can see.
